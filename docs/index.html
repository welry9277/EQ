Query Types

Six Query Variants per Audio Clip

Given an audio clip's human captions, EQ generates six semantically distinct query forms using GPT — from terse key phrases to indirect descriptions.

🎵
Source Caption (middle caption)
"Rain pattering on metal while thunder rumbles in the distance"
key_phrase
Compact noun-phrase label — good for keyword-based retrieval systems.
Rain pattering on metal with distant thunder
statement
Descriptive third-person sentence — closest to natural language search.
There is the sound of rain pattering on metal while thunder rumbles in the distance.
question
Interrogative form — mimics a user asking a search engine.
Can you find a recording of rain pattering on metal while thunder rumbles in the distance?
command
Imperative retrieval command — tests instruction-following in audio search.
Search for a recording of rain pattering on metal while thunder rumbles in the distance.
indirect
Paraphrased, contextual description — tests semantic generalization.
I'm looking for outdoor recordings featuring persistent precipitation against a hard surface with faint storm sounds.
full_caption
Synthesized caption from the full set of human annotations for the clip.
Steady rain is falling and pattering on a metal surface during a storm, while faint thunder rumbles in the distance.
Pipeline

End-to-End Workflow

From raw dataset captions to Recall@K retrieval metrics in four steps.

1

Prepare Captions

Download AudioCaps / Clotho CSVs, or place MeCAT JSON files manually. The loader groups multiple human captions per clip and picks the middle caption as the generation anchor.

2

Generate EQ Variants

Run scripts/makeeq.py to call the GPT API and produce six eq_*.jsonl files per query type, validated and logged automatically.

3

Extract Embeddings

Run scripts/eval_pipeline.py to extract audio, source-text, and generated-text embeddings with LAION CLAP, MGA-CLAP, MS-CLAP, or M2D — then merge into one file per model.

4

Evaluate & Plot

Compute text-to-audio Recall@1/5/10 for each query pool and generate model-wise bar plots — comparing how each query type performs across models.

Quick Start

Get Running in Minutes

Requires Python ≥ 3.9, uv, and an OpenAI API key.

Install
Generate EQ
Evaluate
# Clone the repo
git clone https://github.com/welry9277/EQ.git
cd EQ

# Install dependencies with uv
uv sync --frozen

# Set your OpenAI API key
cp .env.example .env
# Edit .env → OPENAI_API_KEY=sk-...

# Prepare input data (downloads AudioCaps CSVs)
uv run python scripts/prepare_data.py --dataset audiocaps
# Generate all 6 EQ variants for AudioCaps test split
uv run python scripts/makeeq.py \
  --dataset audiocaps \
  --captions-csv input/audiocaps/test.csv \
  --output-dir results/eq/audiocaps_test \
  --split test

# Merge the 6 per-type files into one file per clip
uv run python scripts/merge_eq_by_clip.py \
  --input-dir results/eq/audiocaps_test
# Extract embeddings for all models and merge
uv run python scripts/eval_pipeline.py \
  --config config.yaml \
  --dataset clotho

# Compute Recall@1/5/10 for all query pools
uv run python scripts/eval_text_to_audio_retrieval.py

# Generate bar chart
uv run python scripts/eval_plot_text_to_audio_recall.py
Output Format

JSONL Output Schema

Each line in the generated eq_*.jsonl files follows this structure.

{
  "audio_id":           "4LLWZCuGfgk_26",
  "dataset":            "audiocaps",
  "dataset_slug":       "audiocaps_test",
  "query_type":         "statement",
  "generated_query":    "Water is running and gurgling with a splashing sound.",
  "original_captions":  ["Water is running, gurgling and splashing"],
  "metadata": {
    "split":               "test",
    "eq_reference":        "middle_caption",
    "middle_caption_index": 2,
    "full_caption_count":  5
  },
  "source_model":       "gpt-4o-mini",
  "regen_model":        "gpt-4o-mini"
}
